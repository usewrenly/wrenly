---
title: Guided local installer
description: Prepare a private local Wrenly instance and manage it safely.
---

The `@wrenly/cli` installer prepares a local Wrenly instance for you. It checks your
machine, downloads a verified source release, generates private configuration, builds
Wrenly, and starts its own PostgreSQL database and web/API processes. You choose your
account password in protected browser setup. Invited teammates only visit your web
address and do not install the CLI.

## Prerequisites

- **Linux x86_64 host** — local workstation or self-hosted Linux server on the same computer as your browser
- **[Bun 1.3.14+](https://bun.sh)** — runs the CLI installer and API server
- **[Node.js 24+](https://nodejs.org)** — compiles the Next.js web application
- **[Docker Engine & Compose v2](https://docs.docker.com/engine/install/)** — runs isolated builds, previews, and PostgreSQL (your account needs access to `/var/run/docker.sock`)
- **`util-linux` (`flock`) & 10 GiB+ free disk space** — prevents overlapping steps and leaves room for images and generated projects

The CLI never runs `sudo`, installs system packages, or changes Docker permissions.

## Install with the Wrenly CLI

Inspect prerequisites or preview the exact plan first without changing anything on disk:

```bash
bunx @wrenly/cli@beta doctor
bunx @wrenly/cli@beta plan --directory "$HOME/wrenly"
```

Start the interactive wizard or run `install` directly (passing `install` on a TTY without `--yes` runs interactive prompts for any omitted folder, preset, or port flags, skipping prompts whose flags you already supplied):

```bash
bunx @wrenly/cli@beta
# or explicitly with interactive prompts:
bunx @wrenly/cli@beta install --directory "$HOME/wrenly"
# or non-interactively with a preset:
bunx @wrenly/cli@beta install --preset recommended --yes
```

Pressing Ctrl+C or Esc inside any prompt cancels cleanly with exit code `130` without creating files. Passing `--yes` or running without a TTY skips all interactive prompts after validation.

If a port is occupied, choose another rather than stopping an unrelated service, or let the interactive wizard detect busy ports and propose available replacements:

```bash
bunx @wrenly/cli@beta install \
  --directory "$HOME/wrenly" \
  --web-port 41000 --api-port 41002 --database-port 65433 \
  --previews --preview-port 41003 --databases --yes
```

- `--preset <minimal|recommended|full>` selects a capability bundle (`minimal`: core only; `recommended`: `--previews --laravel --databases --inspection`; `full`: recommended plus `--dictation`). Supported on `install` and `plan`; cannot be combined with individual capability flags.
- Use a short absolute path containing letters, numbers, `/`, `.`, `-`, or `_` under an existing parent directory. Existing destinations and symlink ancestors are refused.
- `--previews` prepares the Next.js preview runtime image (`oven/bun:alpine`).
- `--laravel` builds the repository's Laravel 13 FrankenPHP toolchain (`wrenly/laravel-runtime:13-php8.4`) and should be paired with `--previews` for Laravel previews.
- `--databases` enables Development app databases alongside isolated previews and builds the trusted PostgreSQL (`wrenly/postgres-runtime:17`) and socket (`wrenly/database-socket:1`) images. Production app databases and publishing require a separate server/host connection setup and remain disabled by default.
- `--inspection` enables official framework inspection (`WRENLY_FRAMEWORK_INSPECTION_ENABLED=true`) and builds `wrenly/laravel-runtime:13-php8.4`, `wrenly/framework-inspection-laravel:1`, and `wrenly/framework-inspection-nextjs:1`.
- `--dictation` enables local voice dictation (`WRENLY_DICTATION_ENABLED=true`), downloads checksum-verified Whisper `ggml-base.bin` weights from Hugging Face into `.wrenly/speech/`, and builds `wrenly/transcription-runtime:1`.

## Create your owner account

After an interactive install, the CLI prints a private setup link. On a local desktop
session, it automatically opens the public `/setup` page in your browser without
passing the one-time token in browser arguments; use the private `#setup=` link printed
in the terminal to finish creating your owner account within ten minutes. Do not share
or record that link. A non-interactive installation prints instructions to run:

```bash
bunx @wrenly/cli@beta setup --directory "$HOME/wrenly"
```

Run that in an interactive terminal. It reuses protected owner setup and cannot replace
an existing owner. After sign-in, open **Settings → Providers**, connect your model,
then create a project. If you enabled `--databases`, approve project database storage
and migrations directly in the project conversation; Production databases and publishing
still have their own separate setup guides.

## Start, stop and check

```bash
bunx @wrenly/cli@beta status --directory "$HOME/wrenly"
bunx @wrenly/cli@beta stop --directory "$HOME/wrenly"
bunx @wrenly/cli@beta start --directory "$HOME/wrenly"
```

Start and Stop ask for confirmation; use `--yes` after reviewing the action if needed.
Stop preserves PostgreSQL's volume, accounts, projects, and keys. Start checks the saved
configuration and resource ownership. It never adopts a process just because its port
matches, and it never signals a saved process ID. API/web services run locally and need
an explicit Start after a reboot. This is not a system service or a remote HTTPS setup.

`status --json` returns structured non-secret state. Exit `0` means the requested action
succeeded (or status is running); exit `1` means a check/action failed or remains
unconfirmed; exit `2` means invalid arguments. `doctor` and `plan` also support `--json`
and never install anything.

## Interrupted installation

```bash
bunx @wrenly/cli@beta status --directory "$HOME/wrenly"
bunx @wrenly/cli@beta resume --directory "$HOME/wrenly"
```

Resume requires confirmation and preserves the original keys. A kernel lock prevents
it from overlapping an older command that survived a lost terminal. Committed control
database migrations are recognized by their existing migration journal, rather than
applied twice. Resume does not upgrade a ready installation.

If extraction or private configuration never completed, Resume refuses the partial
installation. Preserve that directory for inspection and choose a different empty
path; do not copy another instance's keys or invent replacement keys. If runtime
ownership is uncertain, Stop leaves the database running rather than risking its data.

Private files live in the installation: `.env`, `apps/web/.env.local`, and `.wrenly/`.
The journal contains release identity and step receipts, not secrets. `.wrenly/runtime.log`
contains local API/web diagnostics and should be treated as private. Back up the root
`.env`, `.wrenly/data`, and the PostgreSQL data together using the backup guide. A source
archive alone is not a backup of accounts or projects.

## Release integrity and scope

This CLI pins public commit `17b5bc9a1955c4793785428bb4e9e1d5f785ca18` and checks the
archive's SHA-256 before extracting or executing source. It rejects links, unsafe paths,
collisions, and oversized archives. `--archive /absolute/source.tgz` accepts only those
same pinned bytes; it does not allow arbitrary code or a moving branch. The checksum
is an integrity check, not a publisher signature. Dependencies come from the pinned
lockfile with installation scripts disabled.

There is no automatic upgrade, uninstall, destructive reset, or telemetry in this version.
The installer does not modify another Wrenly installation.
