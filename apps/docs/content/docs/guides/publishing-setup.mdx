---
title: Set up publishing
description: Configure Gitea, a local private OCI registry, and Coolify to publish built application images.
---

Publishing promotes a sandbox-verified application image through your private repository and
OCI registry to a Coolify deployment host. Once configured here, project owners can click
**Publish** from the workspace toolbar.

## Architecture and single-host support

Publishing connects three infrastructure services outside the core `@wrenly/cli` installer. All
three can run on the same Linux host as Wrenly for single-machine setup and testing, or on
separate hosts on your private network:

| Service | Role | Default local endpoint |
| --- | --- | --- |
| **Gitea** | Stores each published project's private Git repository | Port `3030` (`docker-compose.dev.yml`) |
| **Private Registry** | Stores verified Docker runtime artifacts for Coolify pulls | Port `5001` (`docker-compose.dev.yml`) |
| **Coolify** | Runs the published image and routes HTTP traffic | Port `8000` (standalone Linux install) |

## Prerequisites

- A Linux host with Docker Engine, Compose v2, Bun, Git, `timeout`, and `flock`.
- Core database migrations applied (`bun run db:migrate`).
- Coolify installed on Linux (see the [Coolify installation guide](https://coolify.io/docs/get-started/installation)).
- For Laravel applications, build the Laravel runtime image once from the repository root (or
  install with `@wrenly/cli install --laravel`):

```bash
docker build -t wrenly/laravel-runtime:13-php8.4 packages/sandbox/images/laravel
```

## Step 1 · Configure Gitea

From your Wrenly repository root:

```bash
docker compose -f docker-compose.dev.yml up -d postgres gitea
```

1. Open `http://localhost:3030` and create the initial Gitea user account.
2. Select **+ → New organization** and create an organization (for example `wrenly-apps`).
3. Open **Settings → Applications → Generate new token** with repository and organization write
   scopes, and copy the generated token.
4. Add the Gitea settings to your root `.env`:

```dotenv
WRENLY_GIT_BASE_URL=http://127.0.0.1:3030
WRENLY_GIT_ORG=wrenly-apps
WRENLY_GIT_TOKEN=PASTE_YOUR_GITEA_TOKEN
```

## Step 2 · Start the authenticated local registry

1. Generate credentials for username `wrenly` (skip the `-c` flag if `.local/registry/auth/htpasswd`
   already exists so existing credentials are preserved):

```bash
mkdir -p .local/registry/auth
chmod 700 .local .local/registry .local/registry/auth
docker run --rm -it \
  --user "$(id -u):$(id -g)" \
  --mount "type=bind,source=$(pwd)/.local/registry/auth,target=/auth" \
  --entrypoint htpasswd \
  httpd:2.4-alpine -Bc /auth/htpasswd wrenly
chmod 600 .local/registry/auth/htpasswd
```

2. Start the registry service and verify authentication is enforced:

```bash
docker compose -f docker-compose.dev.yml --profile publishing up -d
curl -i http://127.0.0.1:5001/v2/       # Expected: 401 Unauthorized
curl -i -u wrenly http://127.0.0.1:5001/v2/  # Enter password -> Expected: 200 OK
```

3. Add the registry credentials to your root `.env`:

```dotenv
WRENLY_REGISTRY_URL=http://127.0.0.1:5001
WRENLY_REGISTRY_NAMESPACE=wrenly
WRENLY_REGISTRY_USERNAME=wrenly
WRENLY_REGISTRY_PASSWORD=PASTE_YOUR_REGISTRY_PASSWORD
```

## Step 3 · Connect Coolify

1. Open Coolify (`http://localhost:8000`) and create a project (for example `wrenly-apps`) with
   a `production` environment.
2. Copy the **Project UUID** from the Coolify project URL or settings.
3. Open **Servers**, select the target server (typically `localhost`), and copy its **Server UUID**.
4. Open **Keys & Tokens → API tokens** and create an API token.
5. Add the Coolify configuration to your root `.env`:

```dotenv
WRENLY_COOLIFY_API_URL=http://127.0.0.1:8000/api/v1
WRENLY_COOLIFY_API_KEY=PASTE_YOUR_COOLIFY_TOKEN
WRENLY_COOLIFY_PROJECT_UUID=PASTE_PROJECT_UUID
WRENLY_COOLIFY_SERVER_UUID=PASTE_SERVER_UUID
WRENLY_COOLIFY_ENVIRONMENT=production
```

6. Authenticate Docker on the deployment host against the local registry so Coolify can pull
   promoted images:

```bash
docker login 127.0.0.1:5001
```

## Step 4 · Generate the deployment encryption key and enable publishing

Generate a 32-byte hex key used to encrypt per-deployment environment secrets:

```bash
openssl rand -hex 32
```

Add the key and enable publishing in your root `.env`, then restart Wrenly:

```dotenv
WRENLY_DEPLOY_ENCRYPTION_KEY=PASTE_GENERATED_KEY
WRENLY_PUBLISHING_ENABLED=true
```

## Step 5 · Publish an application

Open a built revision in Wrenly and click **Publish**. Wait for artifact promotion, Coolify
deployment, and health verification to complete, then open the assigned application URL to verify
the live deployment.

## Troubleshooting local verification timeouts

If Coolify reports the container is running while Wrenly remains on **Verifying**:

1. Check the application's assigned domain in Coolify under **Domains / Links**.
2. Probe the endpoint directly from the host:

```bash
curl --max-time 10 -I 'http://YOUR_APP_HOST/'
curl --max-time 10 'http://YOUR_APP_HOST/.well-known/wrenly-deployment'
```

- **Router NAT loopback:** If the direct curl times out, test with
  `curl --resolve 'YOUR_APP_HOST:80:127.0.0.1' 'http://YOUR_APP_HOST/.well-known/wrenly-deployment'`.
  If that returns the deployment UUID, the service is healthy and your router does not reflect
  local traffic through its external address. Map the test domain to `127.0.0.1` in `/etc/hosts`
  for local evaluation.
- **Root route status:** Published applications must return HTTP `200` directly from `GET /`
  (without issuing a `3xx` redirect to `/login`) and expose `/.well-known/wrenly-deployment`.
